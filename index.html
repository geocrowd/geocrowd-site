Collecte et publication d'informations géolocalisées

geocrowd reçoit des points géolocalisés par une API publique, les soumet à une modération dans un back-office, puis les publie au format GeoJSON. Un site public facultatif affiche les points sur une carte et accepte des ajouts. Le logiciel fonctionne sur un hébergement PHP mutualisé, avec une base SQLite.

Fonctionnalités

Collections

Chaque jeu de données est une collection, définie dans un éditeur de schéma : champs, listes de choix, images, liens entre points, description.

API publique

Lecture en GeoJSON avec filtres par emprise, par lien et par champ renseigné. Soumission de points en JSON ou avec des images.

Site public

Facultatif, servi à la racine de l'instance : carte des points publiés, fiche de chaque point, formulaires d'ajout et de proposition de modification générés à partir du schéma.

Modération

Les envois sont publiés après validation dans le back-office. La modération se règle par collection.

Propositions de modification

Correction d'un point publié par le public, avec un commentaire. Le back-office affiche l'état actuel et l'état proposé de chaque champ.

Clés d'API

Accès à l'API restreint par clé, en option. Une clé peut être limitée à des domaines.

Double authentification

Code à 6 chiffres après le mot de passe, par application d'authentification (TOTP) ou par e-mail. Facultative, ou imposée aux comptes admin ou à tous les membres.

Vie privée

Images réencodées sans métadonnées. Adresses IP conservées uniquement sous forme hachée, pendant une heure. Aucun compte demandé au public.

Import OpenStreetMap

Un script remplit une collection à partir d'une requête Overpass et la met à jour sans modifier le statut des points.

Hébergement

PHP 8.1 et SQLite. Ni Composer, ni Node, ni tâche planifiée. Installation par copie des fichiers.

Fonctionnement

Exemple avec une collection de bancs publics.

  1. 1

    Définition de la collection

    La collection et ses champs sont décrits dans l'éditeur de schéma du back-office. L'API renvoie cette définition.

    définition de bancs
    { "id": "bancs", "name": "Bancs publics", "moderation": true,
  "fields": [{ "name": "etat", "label": "État", "type": "select",
               "options": ["Bon", "Abîmé", "Cassé"] }] }
  2. 2

    Envoi d'un point

    Un formulaire, une application ou un script envoie le point à l'API. Chaque champ est validé selon son type.

    POST /api/collections/bancs/points
    curl -X POST https://votre-instance.org/api/collections/bancs/points \
  -H 'Content-Type: application/json' \
  -d '{"lat": 45.764, "lng": 4.8357, "properties": {"etat": "Abîmé"}}'
# {"status":"pending"}
  3. 3

    Modération

    Le point apparaît dans la page Modération du back-office, à sa position sur la carte. Il est validé, modifié, refusé ou supprimé.

  4. 4

    Publication

    Une fois validé, le point est renvoyé par GET /api/collections/bancs/points et affiché sur le site public s'il est activé.

Installation

Prérequis : PHP 8.1 ou supérieur, extensions pdo_sqlite, gd et openssl.

Guide d'installation →

  1. Copie des fichiers sur l'hébergement (archive du dépôt).
  2. Droits d'écriture sur data/.
  3. Création du premier compte sur /admin/, puis activation recommandée de la double authentification.
  4. Création d'une collection dans l'éditeur de schéma.
  5. Activation du site public, en option, dans la page « Site public ».
